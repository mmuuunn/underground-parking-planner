## 8. 우선 결론

1. U1-1의 `UNVERIFIED` 기본 상태와 지하 `NOT_SUPPORTED` 차단은 타당하다.
2. 다음 구현 전에 U1-2 데이터 계약을 실제 평면 3종으로 검증해야 한다.
3. 가장 큰 공백은 기둥망 자체보다 **램프–차로, 코어–보행, 설비–수직 연결을 역할 있는 객체로 표현하지 못하는 것**이다.
4. 이번 PDF만으로 구조 스팬, 방화·피난, 환기·배수, EV 화재 기준을 확정할 수 없다.
5. 실제 평면 12종과 현행 공식 법령 검증 전에는 지하 자동배치를 `VALID`로 표시하면 안 된다.

## 9. 신규 학술 연구 반영 간극

### 9.1 생성기보다 먼저 필요한 중간 표현

S12–S14는 서로 다른 생성·운영 방법을 제시하지만 공통적으로 입력 기하를 곧바로 최종 주차구획으로 바꾸지 않는다. 현재 코드에는 아래 중간 표현이 부족하다.

| 부족한 표현 | 신규 근거 | 현재 간극 | 권고 |
|---|---|---|---|
| 외곽선 방향 후보와 생성 이력 | S12 p.3–5 | 각도·오프셋 후보는 있으나 외곽 세그먼트에서 어떤 방향을 채택했는지 근거가 약함 | 후보마다 `sourceEdge`, 방향, seed, 생성 단계를 기록 |
| 역할 있는 유향 차로 그래프 | S13 p.6–10 | 현행 연결 검사는 동일 평면 접속 위주이며 주차구역 노드·방향·시간 가중치가 없음 | 물리 차로와 운영 방향을 분리한 node/edge 모델 추가 |
| 모듈·인접 규칙 버전 | S14 p.5–9 | `spaces[].kind`만으로 허용 인접관계와 규칙 출처를 표현하지 못함 | 모듈 카탈로그, 회전/대칭, 인접 규칙, 적용 프로필을 별도 버전 관리 |
| 후보군과 Pareto 계보 | S12 p.5; S14 p.9–11 | 최종 score 중심이라 효율·동선 상충과 수동 선택 이유가 사라짐 | 하드 게이트 후 비지배 대안군과 선택 근거 보존 |

### 9.2 검증이라고 부르면 안 되는 범위

- S12의 5개 기존 주차장 대수·㎡/대 비교는 장애물·접근성·회전·보행을 포함한 설계 검증이 아니다.
- S13의 DFS 연결성은 유향 그래프의 도달성만 확인하며 차량 궤적·차로 폭·시야·피난을 확인하지 않는다.
- S14의 실제안 중첩도와 Pareto 평가는 법규 적합성이나 구조·설비 타당성을 증명하지 않는다. 20개 사례의 출처도 인터넷 수집으로 기술되어 제품 검증셋으로 바로 승격할 수 없다.
- 세 논문 모두 법적 규범이 아니므로 수치와 성능 결과를 `ruleProfile`의 법정·발주 하드 제약으로 넣지 않는다.

### 9.3 추가 구현 관문

1. 생성 알고리즘을 선택하기 전에 공통 `입력-제약-생성-검증-목적함수-한계` 계약을 고정한다.
2. `seed`, 규칙 버전, 후보 탈락 사유를 저장해 확률 생성과 brute-force 생성 모두 재현 가능하게 한다.
3. 차로 연결성, 실제 주행 가능성, 보행·피난 연결성을 서로 다른 검증기로 유지한다.
4. 8.4m 그리드·단층 격자·20km/h·피크 임계값 0.8 등은 테스트 fixture에는 쓸 수 있어도 제품 상수로 두지 않는다.
