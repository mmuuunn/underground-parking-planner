## 1. 법령 적용 계층

1. 주차장 유형 확인: 노상 / 노외 / 부설, 자주식 / 기계식, 지평식 / 지하식 / 건축물식.
2. 건축물의 용도·시설면적·세대수 등에 따른 **설치 의무 대수**: 「주차장법」 제19조, 「주차장법 시행령」 제6조·별표 1, 지자체 조례.
3. **배치/기하**: 「주차장법 시행규칙」 제3조, 제6조; 부설주차장은 제11조에 따른 준용 범위를 반드시 적용.
4. **장애인전용주차구역**: 「장애인·노인·임산부 등의 편의증진 보장에 관한 법률」 제17조와 시행령·시행규칙 별표 및 지방자치단체 기준.
5. **차량 진출입/건축·도로·대지 관계**: 건축법, 도로법 및 지자체 관련 조례 등은 실제 대상지 조건에서 별도 판단. 특정 조항만으로 출입구 배치 적합성 보증 금지.
6. 주차장설계 이외의 피난·방화·구조·기계설비·배수·전기·EV 충전시설 등은 별도 모듈. 현재 자동배치 PASS와 분리.
7. **(개정 추가) 레이어 구분:** 이 문서가 다루는 규칙은 **현행 법령 원문 기준**뿐이다. `04_parking/05_domain search/03_analysis/CODEX_DOMAIN_RULES.md`의 PARK-xx·RAMP-xx·AISLE-xx 등 36~44개 항목은 특정 공모지침서·학술 논문에서 추출한 **프로젝트 요구사항(PROJECT_REQUIREMENT)·설계원리(DESIGN_PRINCIPLE)**이며, 그 문서 자체도 "LEGAL=0 — 이번 수집본만으로 현행 법령을 확정하지 않았음"이라고 명시한다. 두 문서를 같은 규칙 테이블에 합치지 말고, 엔진에 반영할 때도 `source_layer: "LAW"` 또는 `"PROJECT"`로 구분해 저장한다.

**주의:** 주차대수 50대 등 기준은 `해당 층 주차대수`, `해당 램프를 이용하는 총대수`, `전체 부설주차장 총대수` 중 어느 것인지 조문별로 구분해야 함.

## 2. 현재 원문 확인 규칙 — 작은 검증 시드 세트

> 이 장의 법령 수치·원문 링크·VERIFIED/PARTIALLY VERIFIED 판정은 원본과 동일하며 이번 개정에서 바꾸지 않았다. 2.1·2.4절에 다른 절을 가리키는 괄호 설명만 추가했다(조문·수치 자체는 불변).

### 2.1 주차구획 최소 치수 — VERIFIED

근거: 「주차장법 시행규칙」 제3조 [2026-07-27 시행]
원문: https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1021077649

| 주차 형식 | 구획 종류 | 최소 너비 (m) | 최소 길이 (m) | 비고 |
|---|---|---:|---:|---|
| 평행 | 경형 | 1.7 | 4.5 | |
| 평행 | 일반형 | 2.0 | 6.0 | |
| 평행 | 보차 미분리 주거지역 도로 | 2.0 | 5.0 | 적용 환경 구분 필수 |
| 평행 외 | 경형 | 2.0 | 3.6 | |
| 평행 외 | 일반형 | 2.5 | 5.0 | |
| 평행 외 | 확장형 | 2.6 | 5.2 | |
| 평행 외 | 장애인전용 | 3.3 | 5.0 | 접근성·동선 별도 필수 |

- 이상의 치수는 **법정 하한**. 도어 개폐·기둥·벽체·실제 주행성까지 보증하지 않음.
- 연속 주차구획 전체 폭/길이 조건은 같은 조 제3항 별도 검증.
- 시드 ID 예: `KR_PARK_STALL_NONPARALLEL_GENERAL_MIN_WIDTH`, `KR_PARK_STALL_NONPARALLEL_GENERAL_MIN_LENGTH`. (4장 통합 스키마의 예시와 동일한 ID — 개정 전에는 4절 예시가 `MIN_` 없이 적혀 다른 ID처럼 보였다.)

### 2.2 주차형식별 차로 폭 — VERIFIED (일반 자동차 대상 노외주차장 표)

근거: 시행규칙 제6조 제1항 제3호 [2026-07-27 시행]
원문: https://www.law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1029242757

| 주차 형식 | 출입구 2개 이상 (m) | 출입구 1개 (m) |
|---|---:|---:|
| 평행 | 3.3 | 5.0 |
| 직각 | 6.0 | 6.0 |
| 60° 대향 | 4.5 | 5.5 |
| 45° 대향 | 3.5 | 5.0 |
| 교차 | 3.5 | 5.0 |

- **제11조에 따라 부설주차장에 준용되는지 적용 경로를 함께 저장**. 노외주차장 표를 무조건 모든 주차장에 적용하지 말 것.
- 출입구 개수, 주차형식, 장애물로 인한 국부 유효폭, 차량 교행 및 진입 방향을 구분.
- 이 표는 주차구획에 접한 차로의 최소폭 규정이지, 모든 램프·회전 접속을 폭 6m로 만들라는 의미가 아님.

### 2.3 지하식·건축물식 차로 조건 — PARTIALLY VERIFIED

근거: 시행규칙 제6조 제1항 제5호 [2026-07-27 시행]
원문: https://www.law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1033040119

- 주차바닥면부터 차로 높이 **2.3m 이상**: 조문 확인.
- **현행 문구는 `경사로의 곡선 부분`에 대한 내변반경으로 확인. **6m**, 주차대수 규모 **50대 이하인 경우 5m**라는 수치가 명시됨. 정확한 주차대수 기준의 적용 범위, 부설주차장 준용·조례 예외는 구현 전 조문 전체와 적용 조건 재확인.
- 경사로 직선부/곡선부 폭, 종단경사도, 기타 세부 규정은 **현 시드에 숫자 미기재**: 제6조 제1항 제5호 다목 이하 원문을 별도로 추출·재검증할 것. 실무에 알려진 수치를 기억으로 코드에 입력하지 말 것.
- **중요한 법령 연혁 충돌:** 법제처 2016년 해석례(15-0764)는 당시 `곡선 부분`이라는 조문을 바탕으로 경사로에 한정되지 않은 모든 차로에 적용된다고 해석했다. 그러나 2026년 조회 원문은 `경사로의 곡선 부분`으로 표시된다. **과거 해석을 현행 모든 차로에 기계적으로 적용해서는 안 된다.** 현행 문구·개정 연혁·적용 시점 재검토 뒤 결정.
- 해석례(역사적 참고): https://www.law.go.kr/expcInfoP.do?expcSeq=315413&mode=2

### 2.4 부설주차장에 대한 준용 — VERIFIED

근거: 시행규칙 제11조 [2026-07-27 시행]
원문: https://www.law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1029242759

- 제11조 제1항: 제6조 제1항의 특정 호 및 제7항 등을 부설주차장에 준용. **각 호별 준용/예외 조건 기록 필수**. (호수 목록 자체는 아직 원문 대조 전 — 8장 미해결 목록 참조)
- 제11조 제4항: 주차대수 **50대 이상** 부설주차장에 설치되는 확장형 주차단위구획에 제6조 제1항 제14호 준용. *확장형 비율 수치 자체는 제14호 원문 확인 후 규칙화*.
- 제11조 제5항: 총 주차대수 **8대 이하**의 자주식주차장에 별도 특례. 단독주택/다세대주택 관련 예외 및 허가권자 인정 요건을 누락하지 말 것.

### 2.5 장애인전용주차구역 접근성 — VERIFIED (해당 출처 별표 기준)

근거: 편의증진법 시행규칙 [별표 1]
공식 문서: https://www.law.go.kr/LSW/flDownload.do?bylClsCd=110201&flSeq=135226913

- 해당 대상의 장애인전용주차구역은 접근 가능한 출입구·승강설비와 가장 가까운 장소에 설치하는 기준이 있음.
- 출입구/승강설비로 이어지는 통로는 높이차가 없어야 하며 **유효폭 1.2m 이상**, 차량 통행로와 분리하도록 규정.
- 따라서 `장애인전용주차면 3.3×5.0m`만 충족해서는 PASS 불가. 접근 동선 전체를 모델링해야 함.
- **면수 비율**은 주차장·대상시설 유형·지자체 별도 기준을 조회하기 전까지 `UNVERIFIED`. 임의 전국 단일비율 지정 금지.
- U3 연결 커넥터가 장애인전용주차면 또는 접근통로를 절단하면 우선 후보 탈락. 자동 재배치 기능은 별도 설계/검증 단계.

### 2.6 설치 의무 대수와 지자체 조례 — VERIFIED (구조)

근거: 「주차장법 시행령」 제6조 및 별표 1 [2026-08-28 시행]
원문: https://law.go.kr/LSW/lsInfoP.do?lsId=004946&urlMode=lsInfoP

- 부설주차장 설치 의무대수는 시설물 종류별로 **시행령 별표 1**에 규정.
- 제6조는 지자체 조례에서 시설물을 세분하거나 기준을 강화·완화, 구역별 차등 설정 가능한 구조를 명시.
- 따라서 의무대수 계산 입력에는 `대상지 행정구역 + 조례 시행일 + 시설용도 + 산정면적/세대수`가 필요.
- **별표 1 전체 시설유형별 수치표와 특정 지역 조례는 이 문서에서 미검증**. 별표 원문/API 파싱 및 실제 지역 시범 수집 이후 확정.

## 3. U3 엔진에 직접 연결되는 규칙 모델

| Rule family | 필요한 입력 | 검사 내용 | 미충족 또는 정보 부족시 |
|---|---|---|---|
| STALL_DIM | 타입, 주차형식, polygon | 법정 최소 너비·길이 | FAIL/UNVERIFIED |
| AISLE_WIDTH | 주차형식, 출입구 수, 차로 유효 geometry | 조문별 최소 유효폭 | FAIL/UNVERIFIED |
| RAMP_CLEARANCE | 층, 보·설비 장애물, 높이 | 통행 공간 유효 높이 | FAIL/UNVERIFIED |
| RAMP_CURVE | 램프 곡선, 내측 경계, 적용 주차대수 | 내변반경·차량 회전 조건 | FAIL/UNVERIFIED |
| RAMP_SLOPE | 시작·종료 레벨, 종단 프로필 | 경사도·전이구간 관련 규정 | 원문 세부 확인 전 UNVERIFIED |
| ACCESSIBLE_ACCESS | 장애인주차 위치, 출입구, 무장애 동선 | 보행거리/폭/단차/차량동선 분리 | FAIL/UNVERIFIED |
| REQUIRED_COUNT | 용도, 면적, 지역·조례, 시행일 | 의무대수 대비 공급대수 | 지역 규정 미확인시 UNVERIFIED |
| GROUND_ENTRY | 도로·대지·보도, 출입구 | 실제 진출입 가능/금지·조건부 | 별도 법규/현장 자료 없으면 UNVERIFIED |

**중요한 제품 경계**
- `GEOMETRY_CONNECTED`는 기하학적 폭 연속성만 의미. `LEGAL_COMPLIANT`, `DRIVABLE`의 동의어가 아님.
- 90° 직각 통로를 폭만 확장해 연결했다면 `GEOMETRY_CONNECTED=true`, `DRIVABLE=UNVERIFIED` 가능.
- 주차대수 우선 순위로 법정 주행 제약이나 장애인 접근 동선 보호를 희생해서는 안 됨.

## 4. 법규 데이터 파일 구조 — 단일안 (기존 저장소 매핑)

> 원본 4절과 5.1-D는 서로 다른 번호 트리(`01_law_sources/02_law_extracted/...` vs `01_law_sources/02_law_raw/...`)를 제안했고, 둘 다 실제 저장소에 이미 있는 `04_parking/05_domain search/02_research_notes`, `03_analysis` 번호와 충돌한다. 이 절이 두 제안을 **대체**하는 단일안이다.

실제 저장소에는 이미 다음이 있다 (2026-10-21 확인):

```text
04_parking/05_domain search/
  01_sources/              # 공모지침서·가이드라인 원문 PDF (법령 아님)
  02_research_notes/       # 조사 메모 (.md)
  03_analysis/             # CODEX_*.md, CLAUDE_*.md 분석 문서
  04_plan sample/          # DXF 공모 사례 11건 (법령·PDF와 섞지 않음)
04_parking/02_tests/       # 엔진 테스트 (U3 등 기존 테스트 트리)
```

법령 자료는 새 번호 트리를 만들지 않고 기존 폴더 아래 `law/` 하위 디렉터리로 얹는다:

```text
04_parking/05_domain search/
  01_sources/law/           # 법령 원문 응답(XML/JSON/PDF 등 원본), 식별자·해시·시행일, SOURCE_MANIFEST.md
  03_analysis/law/           # 추출 규칙 후보(JSON), 원문-후보 대조표, 승인/보류 이력, 검증 완료 규칙
04_parking/02_tests/law/     # 경계값·예외·준용·개정 회귀 테스트 (기존 02_tests 트리 아래)
```

- `02_research_notes/`, `04_plan sample/`은 그대로 유지하고 법령 자료를 넣지 않는다.
- 실제 폴더명이 이후 또 달라지면, 새 트리를 만들기 전에 반드시 디렉터리 조사 후 이 매핑을 갱신한다.

## 4.1 개별 규칙 필수 필드 — 통합 스키마

> 원본 4절의 YAML과 5.1-E의 JSON, 두 가지 스키마가 서로 다른 필드명(`legal_basis.article` vs `source.article`, `effective_date` vs `effective_from/until`)으로 같은 대상을 정의했다. 아래 하나로 합친다. **5.1-E의 JSON 구조를 기준으로 하고, 4절 YAML에만 있던 `rule_version`, `jurisdiction`, `result_scope`, `notes`를 흡수했다.** 이 JSON은 **규칙 레코드**(법령 조문을 정규화한 것)만 담는다. 특정 설계안에 이 규칙을 적용한 결과(`evaluation_result`)는 아래 4.1.1절의 별도 **평가 레코드**에 기록하며, 이 규칙 JSON에는 넣지 않는다.

```json
{
  "rule_id": "KR_PARK_STALL_NONPARALLEL_GENERAL_MIN_WIDTH",
  "rule_version": 1,
  "jurisdiction": "KR",
  "source": {
    "law_id": "<법령ID>",
    "mst": "<버전번호>",
    "article": "제3조 제1항 제2호",
    "source_url": "<원문URL>",
    "accessed_date": "2026-10-21",
    "sha256": "<원문해시>"
  },
  "effective_from": "2026-07-27",
  "effective_until": null,
  "scope": {
    "parking_type": "accessory",
    "parking_method": "self_parking",
    "stall_layout": "non_parallel",
    "stall_type": "general"
  },
  "check": {"property": "stall.width_mm", "operator": ">=", "value": 2500, "unit": "mm"},
  "result_scope": "geometry_only",
  "exceptions": [],
  "derivation": "원문 제3조의 조건과 제11조 준용 관계 확인 필요",
  "verification_status": "EXTRACTED",
  "reviewer": null,
  "reviewed_at": null,
  "notes": "다른 법규, 지자체 추가 기준, 기둥·벽체 간섭은 별도 평가"
}
```

필드 설명:

- `verification_status` (자료 생명주기, 이 규칙 레코드에만 있음): `RAW → EXTRACTED → REVIEW_NEEDED → VERIFIED → SUPERSEDED`. **`VERIFIED`는 "조문 원문과 수치가 일치함"만 의미하고, 제품 운영 승인을 의미하지 않는다.** 제품 운영 승인은 이 스키마의 범위 밖이며, 별도의 승인 절차(승인 체크리스트·계약 등)로 관리한다 — 운영 승인 정보를 `notes`나 다른 임의 키에 끼워 넣지 않는다.
- `reviewer` / `reviewed_at`: 원문-후보 대조를 수행한 사람과 시각 (조문 검증 기록이며, 운영 승인 기록이 아니다).
- `result_scope`: 이 규칙이 어떤 범위까지 보증하는지 (예: `geometry_only` — 기하 치수만 확인, 주행성·구조·설비는 보증하지 않음).
- `scope.parking_type`은 「주차장법」 제2조의 법정 유형이다 — 의미와 enum은 4.2절 참조.

### 4.1.1 평가 레코드 — 규칙과 분리된 별도 레코드

규칙 레코드(위 JSON)는 법령 조문 자체의 정규화다. 이 규칙을 **특정 설계안**에 적용한 결과는 아래처럼 별도 레코드에 저장한다. 저장 단위가 다르다: 규칙 레코드는 `rule_id`당 1건, 평가 레코드는 `(plan_id, rule_id)` 조합당 1건이다.

```json
{
  "plan_id": "<설계안 ID>",
  "rule_id": "KR_PARK_STALL_NONPARALLEL_GENERAL_MIN_WIDTH",
  "evaluation_result": "PASS",
  "evidence": "<측정값·대상 객체 ID 등 판정 근거>",
  "evaluated_at": "<YYYY-MM-DDThh:mm:ssZ>"
}
```

- `evaluation_result`: `PASS / FAIL / UNVERIFIED / NOT_APPLICABLE`.
- 참조하는 규칙 레코드의 `verification_status`가 `VERIFIED`가 아니면 `evaluation_result`는 항상 `UNVERIFIED`로 강제한다.
- `evidence`는 PASS/FAIL 판정의 근거(측정값, 기하 객체 ID 등)를 남겨 재현 가능하게 한다.

### 폐기된 초안 (참고용, 구현 기준 아님)

원본 4절 YAML은 아래와 같았다. 필드명이 위 통합 스키마와 달라 혼동을 일으키므로 **구현에는 쓰지 않는다**.

```yaml
# 폐기된 초안 — 참고용. 위 4.1절 JSON 스키마를 대신 사용할 것.
rule_id: KR_PARK_STALL_NONPARALLEL_GENERAL_WIDTH   # MIN_ 누락 — 4.2절 명명 규칙 위반
status: VERIFIED
jurisdiction: KR
parking_type: [off_street, accessory]   # 법정상 나란한 유형 둘을 배열로 섞음 — 4.2절 충돌의 원인, 통합 스키마는 scope.parking_type 단일 값(현재 accessory)
applicability:
  parking_method: self_parking
  stall_layout: non_parallel
  stall_type: general
legal_basis:
  law_name: 주차장법 시행규칙
  article: 제3조 제1항 제2호
  effective_date: '2026-07-27'
  source_url: https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1021077649
  accessed_date: '2026-10-21'
  verified_by: human_review_required_for_production
constraint:
  operator: '>='
  property: width_mm
  threshold: 2500
  unit: mm
result_scope: geometry_only
exceptions: []
notes: 다른 법규, 지자체 추가 기준, 기둥·벽체 간섭은 별도 평가
```

## 4.2 명명·enum 통일

- `rule_id`는 항상 극값 표시(`MIN_`/`MAX_` 등)를 포함한다. 예: `KR_PARK_STALL_NONPARALLEL_GENERAL_MIN_WIDTH` (2.1절·4.1절과 동일하게 통일). 원본 4절 예시처럼 `MIN_`을 생략한 ID는 쓰지 않는다.
- `scope.parking_type`은 「주차장법」 제2조가 서로 나란히 정의하는 법정 세 유형 중 하나의 단일 값이다: `on_street`(노상), `off_street`(노외), `accessory`(부설). 부설주차장은 노외주차장의 하위 유형이 아니다. 현재 범위는 `accessory`뿐이며 `on_street`·`off_street`는 범위 밖이라 쓰지 않는다. `parking_subtype` 필드는 두지 않는다.
  - 원본 초안의 `parking_type: [off_street, accessory]` 배열과 이전 개정의 `off_street`+`parking_subtype: accessory` 구조는 모두 폐기한다 (법정 유형을 계층으로 잘못 표현).
  - 이전 초안에서 쓰던 `attached`는 `accessory`로 대체했다.
  - 법정 유형과 별개의 위치 특성(예: 지하식·건축물식·지평식)이 규칙 조건으로 필요해지면 `parking_type`과 무관한 다른 필드로 설계한다. 지금은 추가하지 않는다.
- `scope.parking_method`(운용 방식)은 `self_parking`만 쓴다. `self_driving`은 같은 뜻의 중복 표현이므로 제거.
- 기계식 주차는 현재 범위 밖이다. 범위에 포함되는 시점에 `mechanical` 등을 enum에 추가한다 (지금은 추가하지 않음).

7. 해당 지자체 조례와 위임 관계 확인. **조례 우선 적용 여부를 각 규칙에 명시**.
8. 사람이 원문과 추출 결과를 대조하고 실무 검토한 후 `VERIFIED` 승인 (4.1절의 `verification_status`).
9. 경계값 테스트: 49/50/51대, 8/9대, 2,499/2,500mm 등. 실제 임계값의 비교 연산자가 `이상/초과/이하/미만` 중 무엇인지 검증.
10. 변경 감지 시 규칙을 자동 갱신하지 말고 `REVIEW_NEEDED` 처리. 재검증 전 기존 버전 보존 및 적용 중단/고지 정책.

## 5.1 공식 API 구축 방법론 — Codex 전달 실행 명세

### A. 접근 권한부터 확보

1. [국가법령정보 공동활용 OPEN API 신청](https://open.law.go.kr/LSO/usrJoin.do)에서 신청한다. 서비스명·활용 목적·서버 IP/도메인(해당 시)·접근 분야·본문 XML/JSON 등 신청 정보를 작성한다. `OC`는 신청자가 지정하는 API 인증값이며, 신청 후 **API인증키관리**에서 확인한다.
2. 인증값은 저장소에 커밋하지 않는다. 로컬 환경변수 또는 gitignore된 `.env`를 사용한다. 로그·예제·오류 보고에도 인증값을 마스킹한다.
3. 개발 환경이 `localhost`이거나 별도 서버 IP가 없다면 신청 가능한 설정과 접근 제약을 공식 안내/운영자에게 확인한다. **임의 IP를 등록하거나 권한 없이 크롤링해 우회하지 않는다.**
4. 호출 한도, 이용조건, 허용 콘텐츠 형식, 저작권/재배포 조건은 실제 계정의 승인 내용과 최신 운영 정책을 확인한다. 호출량은 문서에 근거 없는 수치로 고정하지 않는다.

### B. 실제 제공되는 API (공식 가이드 확인)

| 목적 | HTTP 엔드포인트 | 핵심 파라미터 | 주의 |
|---|---|---|---|
| 현행 법령명 검색 | `https://www.law.go.kr/DRF/lawSearch.do` | `OC`, `target=law`, `type=XML`, `query`, `page`, `display` | 검색 결과의 법령ID와 시행일·법령일련번호를 저장 |

### C. 최소 수집 루프

1. **시드 법령 고정:** `주차장법`, `주차장법 시행령`, `주차장법 시행규칙`, `장애인·노인·임산부 등의 편의증진 보장에 관한 법률` 및 그 하위 법령. 각 법령의 식별자 확인 후 고정한다.
2. **목록 조회 → 법령 버전 선택:** 조회 시각(`retrieved_at`)과 설계 적용 기준일(`effective_on`)을 분리한다. `법령ID`, `MST`, `공포일`, `시행일`, `현행/연혁`을 기록한다.
3. **본문 원본 보존:** 응답 전체를 변형 없이 저장하고 SHA-256 해시를 생성한다. 실패·빈 응답·인증 오류를 정상 데이터로 기록하지 않는다.
4. **필요 조항 추출:** 제3조·제6조·제11조, 시행령 제6조와 별표 1 등 우선순위 조항만 조문 단위로 파싱한다. 별표, 부칙, 위임·준용 링크를 각각 별도 개체로 보존한다.
5. **규칙 후보 추출:** 치수/수량만 추출하지 말고 대상 시설·주차형식·예외·지역·시행일·단위·비교연산자를 함께 추출한다. 일단 `EXTRACTED` 상태(4.1절 `verification_status`)를 준다.
6. **전문가 대조:** 원문 스냅샷과 규칙 후보를 1:1 대조해 `VERIFIED`로 승격한다. 불명확하면 `REVIEW_NEEDED` 유지.
7. **규칙 엔진 반영:** `VERIFIED`된 규칙만 런타임 참조 대상으로 빌드/승인한다. 수집 로직과 설계 계산 코드를 분리한다.
8. **변경 감지:** 재조회 결과와 기존 원문 해시·시행일을 비교하여 차이가 있으면 변경 후보를 발행한다. **자동으로 판정 기준을 덮어쓰지 않는다.**

### H. Codex에 전달할 추가 요청문 (개정)

> 이 문서 5.1절을 기준으로 법제처 공식 API 연동의 설계안을 작성해라. **인증값(OC) 신청과 Windows 사용자 환경변수 설정은 완료됐다. 다만 실제 엔드포인트 응답 형식, 호출 권한, 이용조건은 아직 검증되지 않았고 시범 지자체도 미선정이다.** 인증값 자체를 읽거나 출력하거나 문서·로그·저장소에 기록하지 말고, "설정 완료/검증 전" 상태만 참고해 다음 단계(실제 호출 테스트 설계)를 제안해라. **파일 배치는 4절의 단일 매핑(`04_parking/05_domain search/01_sources/law/`, `03_analysis/law/`, `04_parking/02_tests/law/`)을 그대로 따르고, 새로운 번호 트리(`02_law_raw`, `03_law_extracted` 등)를 제안하지 마라 — 이미 그 번호는 `02_research_notes`, `03_analysis`가 쓰고 있다.** 첫 범위는 주차장법 시행규칙 제3·6·11조로 제한하고, 각 규칙의 원문 근거·시행일·적용 조건·준용·예외·검증 상태를 4.1절 통합 스키마로 보존해라. **API 게이트는 단계별이다 (5.1-I 참조): 이 문서의 교차검토가 끝나고 사용자가 승인하면 비밀값을 출력하지 않는 최소 1회 접근시험만 허용하고, 반복/대량 호출·원문 수집·수집기 구현·엔진 반영은 시범 지자체 선정과 접근시험 결과의 사용자 승인 전까지 금지한다.** 수집 결과는 설계 엔진으로 자동 반영하지 마라. 기존 DXF 및 엔진 코드는 수정하지 말고 수집기 구현 전 설계·시험·권한 체크리스트부터 제출해라.

### I. API 게이트 단계 (순환 조건 해소)

응답 형식·호출권한은 접근시험 없이는 확인할 수 없으므로, 호출 금지를 한 덩어리로 두지 않고 단계로 나눈다.

| 단계 | 허용 범위 | 진입 조건 |
|---|---|---|
| G0 (현재) | 호출 일체 금지. 설계·문서만 | — |
| G1 | 비밀값을 출력하지 않는 **최소 1회 접근시험**. 결과에는 HTTP 상태·응답 형식(XML/JSON 등)·오류 분류만 기록. OC와 응답 원문은 저장하지 않음 | 이 문서의 교차검토 완료 + 사용자 승인 |
| G2 | 반복/대량 호출, 원문 수집, 수집기 구현, 엔진 반영 | 시범 지자체 선정 + G1 결과의 사용자 승인 |

## 7. Codex 전달용 작업 요구사항 (개정)

> 현재 주차장 자동배치 프로젝트의 법규 도메인 수집을 설계하라. 이 MD를 기준으로 **구현 전 수집·검증 계획과 대상 파일 목록**을 먼저 제출하라. 공식 국가법령정보센터 API를 우선 검토하고, API 사용권한을 확보하지 못한 경우 권한 없는 대량 스크래핑을 수행하지 마라. 자동 추출 결과는 4.1절의 `verification_status`(`RAW/EXTRACTED/REVIEW_NEEDED/VERIFIED/SUPERSEDED`)로 두고 원문·시행일·적용 조건·예외·준용·조례를 검증하지 않은 수치를 엔진 하드코딩으로 반영하지 마라. 우선 자주식 부설주차장에 직접 필요한 제3조·제6조·제11조와 장애인 접근성 관련 조항만 다루고, 실제 U3의 기하학적 연결 성공을 법령·주행 적합성과 분리하라(`evaluation_result`는 4.1.1절의 별도 평가 레코드에만 기록하고 규칙 레코드에는 넣지 않는다). **파일 배치는 4절 단일 매핑을 따르고, `04_plan sample`의 DXF 공모 사례와 법령 원문을 같은 폴더에 섞지 마라.** **인증값(OC) 환경변수 설정은 완료됐으나 실제 엔드포인트 응답 형식·호출권한·이용조건은 미검증이고 시범 지자체도 미선정이다. 문서 교차검토 후 사용자 승인이 나기 전에는 어떤 호출도 하지 말고, 승인 후에도 5.1-I의 최소 1회 접근시험까지만 허용된다. 반복/대량 호출, 원문 수집, 수집기 구현, 엔진 반영은 시범 지자체 선정과 접근시험 결과 승인 전까지 금지한다.** 기존 DXF 검증 사례나 주차 배치 코드를 수정하지 말고, 승인 전에는 도메인 데이터 수집·시험 계획까지만 제안하라.
