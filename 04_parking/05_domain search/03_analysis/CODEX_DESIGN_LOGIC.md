# CODEX 지하주차장 공간 관계와 자동설계 논리

검토 완료일: 2026-10-20  
표 안의 `문서 확인`은 수집 원문에 있는 내용이고, `CODEX 제안`은 이를 자동설계 문제로 번역한 가설이다. 두 항목을 같은 사실로 취급하지 않는다.

## 1. 주차구획보다 먼저 결정할 것

| 우선 요소 | 문서 확인 | CODEX 제안 | 상태 |
|---|---|---|---|
| 층 외곽·굴착 가능 범위 | LH 공통지침은 지하수·암반·외부 유입수·층수 형식을 먼저 고려 | 각 층의 실제 사용 외곽을 입력하고 출처·확정도를 저장 | 즉시 모델 가능 |
| 지상 도로와 차량 접속점 | 사업지침은 진입도로·램프 위치·대기·시야를 요구 | 외부도로 → 지상 출입구 → 램프 상부 → 하부 착지 → 층 차로를 하나의 연결 그래프로 관리 | 연결 검증 필요 |
| 램프 전체 형상 | 폭·경사·반경·평탄부가 점유 공간을 결정 | 상·하층 윤곽, 착지부, 전이구간, 경사 프로파일을 구획 전에 예약 | U1 계약 보강 |
| 코어·보행 접근점 | 주동 통합, 연결통로 최소, 장애인 접근 원리가 반복 | 코어 외곽만이 아니라 엘리베이터·계단·문·접근 가능 여부를 저장 | U1-2 필요 |
| 전기실·저수조·샤프트·집수정 | 공모 도서가 이 공간들을 포함하도록 요구 | 일반 장애물 한 종류가 아닌 역할·연결·유지관리 면을 가진 예약 공간 | U1-2 필요 |
| 방화·피난 구획 | 학교 가이드가 양방향 피난·방화구역을 요구 | 방화벽·셔터·피난코어·제연구역 객체를 열되 수치 판정은 공식 근거 전 보류 | OPEN QUESTION |
| 구조 기준선 | 사업별 구조형식은 있으나 스팬 수치는 없음 | 구조망은 선행 입력형과 후행 제안형을 구별하고 둘 다 구조 미검증 표시 | 실제 평면·구조자료 필요 |

## 2. 권고 배치 순서

| 단계 | 공간 결정 | 이유 | 결과 상태 |
|---:|---|---|---|
| 1 | 프로젝트·용도·발주조건·현행 법규 프로필 선택 | 같은 LH 문서군에서도 비율·구조·층고가 다름 | 근거 없으면 `UNVERIFIED` |
| 2 | G/B1/B2 외곽, 표고, 층고, 유효높이 입력 | 평면과 단면을 함께 고정 | 기하 입력 |
| 3 | 도로 접속점과 램프 전체 형상·착지부 배치 | 램프는 면적 차감물이 아니라 층간 차량 연결 | L1/L2 연결 후보 |
| 4 | 코어·출입문·방화/피난 연결 배치 | 장애인·일반 보행의 목적지 결정 | 보행 그래프 입력 |
| 5 | 설비실·샤프트·저수조·집수정·환기 개구 예약 | 주차 뒤 남는 자투리로 처리하면 연결·유지관리 실패 가능 | 예약 공간 |
| 6 | 구조 방식·기준선의 확정도 선택 | 고정 구조망인지, 개념 제안인지 알고 탐색해야 함 | `fixed` 또는 `proposal` |
| 7 | 주차/차로 후보 생성 | 위 요소를 제외·연결 조건으로 사용 | 후보일 뿐 `VALID` 아님 |
| 8 | 특수구획·보행통로 배정 | 코어 접근성과 시설 전체 요구량을 함께 만족 | 프로젝트 규칙 감사 |
| 9 | 차량·보행·피난·구조·설비 검증 | 서로 다른 네트워크를 별도 검사 | 영역별 PASS/FAIL/UNVERIFIED |
| 10 | 대수·효율·동선·공사성 비교 | 유효 후보끼리 최적화 | 대안 순위 |

## 3. 질문별 판단

### 3.1 주차구획 전에 반드시 정할 요소

층 외곽, 램프와 착지부, 코어의 실제 접근점, 필수 설비·샤프트, 방화·피난 경계의 입력 가능 상태가 먼저다. 구조망은 프로젝트가 이미 정한 경우 선행 고정 조건이고, 공모 초기 미정인 경우에는 결과와 함께 제안하되 설계 확정으로 표시하지 않는다.

### 3.2 램프·코어·설비·기둥 관계

| 요소 | 선행 관계 | 상호 검증 |
|---|---|---|
| 램프 | 외부도로·층고 뒤, 주차열 전 | 상하층 차로 접속, 전이구간, 대기·시야 |
| 코어 | 주동 출입구·피난 전략과 함께, 특수구획 전 | 보행거리, 횡단 수, 접근 가능 엘리베이터 |
| 설비 | 용량은 별도 설계, 위치 예약은 주차열 전 | 외기·수직 샤프트·배수 최저점·유지관리 접근 |
| 기둥 | 구조안 있으면 주차와 동시 제약; 없으면 주차 모듈과 공동 탐색 | 구획 문 열림·차로·보행, 층간 연속, 상부 전이 |

문서는 이 네 요소의 완전한 순서를 규정하지 않는다. 위 순서는 **CODEX 제안**이며 실제 평면 12종으로 검증해야 한다.

### 3.3 최대 대수와 합리적 동선의 구별

| 종류 | 지표 | 판정 방식 |
|---|---|---|
| 하드 유효성 | 구획·차로 비침범, 램프 연결, 프로젝트 폭·높이, 필수 특수구획 | 하나라도 실패하면 후보 탈락 |
| 동선 품질 | 순환 가능성, 막다른 길이·회차, 코어까지 거리, 차로 횡단, 램프까지 거리 | 유효 후보의 점수 비교 |
| 효율 | 총 대수, ㎡/대, 비정형 잔여면적 | 품질 기준 통과 뒤 최적화 |
| 운영 | 출입구 분산, 주동군별 배분, 방문·하역·EV 구역 | 용도 프로필별 점수·제약 |

대수만 많은 후보는 차량 회전·보행·피난·설비 연결이 미검증이면 합리적 배치로 승격할 수 없다.

### 3.4 순환형과 막다른 차로

- **문서 확인:** 학교 가이드는 순환형을 명시하고, 대전소제는 막다른 차로를 피하거나 회차 공간을 요구한다.
- **CODEX 제안:** 순환형을 우선 점수로 두되 모든 용도에 절대 하드 제약으로 만들지 않는다. 막다른 가지는 길이, 서비스 구획 수, 끝단 회차 공간, 실제 차량 궤적을 검사한다.
- **OPEN QUESTION:** 허용 막다른 길이와 회차부 표준은 수집본에 없다.

### 3.5 기둥망과 주차 모듈

- **문서 확인:** 구조 형식은 사업별로 주어지지만 일반 기둥 스팬·단면은 없다.
- **CODEX 제안:** `structuralSystem`, `gridAxes`, `columnFootprints`, `certainty`를 분리한다. 고정형은 축·기둥이 입력된 상태에서 주차를 풀고, 제안형은 주차열 경계·차로 가장자리에서 후보 축을 만든다.
- **OPEN QUESTION:** 허용 스팬 범위, 기둥 단면, 보/무량판 단면, 전이구조 비용은 구조 엔지니어 자료가 필요하다.

### 3.6 차량·보행 동선 검증

| 네트워크 | 시작–끝 | 최소 검증 | 아직 필요한 것 |
|---|---|---|---|
| 차량 | 외부도로–출입구–램프–각 구획 전면 | 연속 폭, 접속, 교차·막다름 | 회전 궤적, 일방통행, 시야 |
| 일반 보행 | 각 구획–건물/코어 출입문 | 연결, 장애물·차로 교차 | 문·계단·승강기 운영 |
| 장애인 보행 | 장애인 구획 승하차면–접근 가능 코어 | 단차 없는 후보, 거리, 횡단 | 경사, 문 유효폭, BF 상세 |
| 피난 | 주차 영역–방화구획 출구–피난계단–피난층 | 구획별 경로 존재 | 현행 거리·계단·방화문 법규 |

한 개의 “연결됨” 플래그로 네 네트워크를 합치면 안 된다.

### 3.7 하드 제약과 평가 기준

| 하드 제약 후보 | 조건 |
|---|---|
| 프로젝트 명시 비율·치수·높이·폭 | 해당 프로젝트 프로필과 근거 페이지가 선택된 경우 |
| 기하 비침범·층 외곽 포함 | 항상 |
| 램프의 양쪽 층과 차로 연결 | 지하 후보 생성 시 항상 |
| 필수 공간 존재 | 사용자/프로젝트가 필수로 지정한 코어·설비·구획 |
| 현행 법규 | 공식 원문·시행일·적용 범위를 별도 검증한 경우에만 |

| 평가·최적화 기준 | 이유 |
|---|---|
| 총 대수·㎡/대 | 유효 대안 간 효율 비교 |
| 순환 고리·막다른 길이 | 용도와 운영 방식에 따라 선택 가능 |
| 코어 거리·차로 횡단 수 | 정량 하한이 자료마다 불충분 |
| 램프 길이·지상/지하 손실 | 비용·공간 품질의 trade-off |
| 환기 개구 분산·자연채광 | 기계설비 계산 전 개념 평가 |
| 구조 규칙성·층간 연속 | 구조 계산 전 개념 평가 |

## 4. OPEN QUESTION

1. 실제 12개 평면에서 램프·코어·설비·기둥 결정 순서가 어떻게 나타나는가?
2. 용도별 허용 막다른 차로 길이와 회차 형상은 무엇인가?
3. 구조 방식별 경제적인 스팬·기둥 단면 범위와 상부 주동 전이 조건은 무엇인가?
4. 방화구획·피난거리·제연/배연의 2026 현행 적용 조건은 무엇인가?
5. 기계환기·전기실·저수조·집수정의 초기 면적 예약 모델을 만들 수 있는가?
6. EV 충전구역의 소재지별 의무 비율과 지하 화재 안전 조건을 어떻게 버전 관리할 것인가?
7. 장애인 구획의 시설 전체 배분과 층별 우선 배분을 어떤 규칙으로 연결할 것인가?

## 5. 신규 학술 연구를 반영한 생성·선택 논리

### 5.1 공통 파이프라인

| 단계 | 입력/처리 | 산출물 | 근거와 경계 |
|---:|---|---|---|
| 1 | 외곽, 출입구, 고정 코어·램프·설비·구조와 프로젝트 프로필 입력 | 출처·확정도가 있는 문제 정의 | S12·S14의 외곽/출입구 입력을 확장. 논문 실험 치수는 주입하지 않음 |
| 2 | 물리 차로 후보와 주차 가능 셀/띠 구성 | 방향 미지정 물리 네트워크와 가용 영역 | S12의 외곽/내부 방향, S14의 셀 분해는 선택 가능한 생성 전략 |
| 3 | 모듈·격자 또는 기존 엔진으로 다수 후보 생성 | seed·규칙 버전이 있는 후보군 | WFC 구현을 의무화하지 않으며 모듈 방식은 직교망 적합성을 먼저 판단 |
| 4 | 기하·프로젝트 제약과 차량 그래프 도달성 검사 | 탈락 사유가 명시된 유효 후보 | S13의 연결성 원리를 사용하되 회전·폭·시야 검증과 구별 |
| 5 | 보행·피난·구조·설비 검증 | 영역별 PASS/FAIL/UNVERIFIED | 세 논문이 생략한 범위를 기존 관문으로 유지 |
| 6 | 대수·㎡/대·차로 품질·동선 지표 계산 | 목적별 점수 벡터 | 단일 대수 최대화로 축약하지 않음 |
| 7 | 비지배 대안군과 운영 시나리오 비교 | Pareto 후보와 선택 근거 | S14의 MOO, S13의 피크 운영 평가는 건축 배치와 운영을 분리해 적용 |

### 5.2 생성 전략별 사용 조건

| 전략 | 적합한 입력 | 반드시 붙일 검증 | 사용 금지 또는 보류 조건 |
|---|---|---|---|
| 외곽 방향 + 내부 격자 열거 | 비정형 외곽의 초기 대수 탐색 | 고정 장애물, 출입구·보행, 차량 회전, 프로젝트 규칙 | S12 결과를 완성 설계로 표시 금지 |
| 모듈 인접 규칙 + WFC | 반복 셀과 인접 규칙을 신뢰성 있게 정의한 경우 | 모순, 전체 연결, 불필요 차로, 불규칙 구획, seed 재현 | 8.4m 고정망이 아닌 프로젝트에서 규칙 재작성 없이 적용 금지 |
| 유향 그래프 조합 | 이미 형성된 물리 차로망의 운영 방향 비교 | 전 구역 진입·이탈, 실제 제어 가능성, 저수요 복귀 전략 | 최초 평면 생성기로 오인 금지; 가변 제어설비 없으면 참고만 |

### 5.3 목적함수와 검증의 분리

- `검증`: 공식 법규·선택된 프로젝트 요구, 기하 비침범, 램프 양단 연결, 필수 공간, 차량/보행/피난 그래프의 영역별 관문이다.
- `목적함수`: 대수, ㎡/대, 유효/불필요 차로, 순항시간, 코어 거리처럼 유효 후보 사이의 선호를 비교한다.
- `실험 파라미터`: S12의 사례별 차로·구획 치수, S13의 0.8·1:4/4:1·20km/h, S14의 8.4m·77모듈·278규칙은 논문 재현용 메타데이터다.
- 최종 후보는 목적함수 우수성만으로 `VALID`가 되지 않으며, 미구현 검증이 하나라도 있으면 해당 영역을 `UNVERIFIED`로 유지한다.
