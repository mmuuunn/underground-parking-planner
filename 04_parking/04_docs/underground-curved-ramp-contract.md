## 1. 범위

| 포함 | 범위 밖(이후 단계) |
|---|---|
| 램프 1개, 원호 1개 + 위·아래 직선(각 0 이상) | 여러 램프, 진입·진출 램프 두 개(다음 단위) |
| 1차로·2차로, 좌회전·우회전 | 회전각 360° 이상, 몸체가 스스로 겹치는 배치(나선) |
| 회전각 0° 초과 **360° 미만** | 완화 곡선(클로소이드), 편경사 |
| 한 층 고저차 | 도로 접속 3m 구간 경사(직선 8.5%·곡선 7%, R06, 단계 3), 유효높이(R07) |
| 완화구간 길이 입력과 구간 출력(R04용) | 차량 궤적 판정(V06, 단계 5) |

직선 생성기(`createStraight`)와 기존 직선 결과는 그대로 둔다. 기준 다섯 형태의 기대값은 바뀌면 안 된다.

## 2. 측정 기준 (사용자 결정 2026-10-26)

법조문은 측정 위치를 정하지 않는다. 아래는 사용자 결정이며 국내 공식 측정선이 확인된 것으로 설명하지 않는다.

| 기준 | 결정 | 근거 등급 |
|---|---|---|
| 내변반경 `R_in` | **안쪽 벽 마감면**(안목)의 반경 | 관행: 실무 블로그 "주차장 곡선 경사로의 내변반경 적용하는 법"(위니의 건축이야기, 2021-03-02, https://winnie-architecture.tistory.com/39). 연석 기준보다 보수적 |
| 법령상 차로 너비 `W` | 양쪽 연석의 **벽 쪽 끝 사이**(연석 포함, 벽–연석 사이 제외) | 보수적 선택. 조문은 "연석 부분은 너비에 포함"만 명시. 같은 블로그는 벽–벽을 W로 봄 |
| 경사 측정선 `R_g` | **(v0.3 사용자 결정) 안쪽 차로 중심선**: 2차로 안쪽 연석 벽 쪽 끝 + W/4, 1차로 + W/2. 예: R_in 6,000·간격 300·W 6,500 → 7,925. v0.2의 보수적 측정선(안쪽 벽 + W/4 = 7,625)은 내부 설정 `conservativeInner`로 남김 | 관행(같은 블로그, 2018-06-01 질의의 "안쪽 차로 중앙선" 운영 관행) |

**"보수적"의 비교 범위**: 측정선은 실제 차로 중앙보다 안쪽(벽–연석 간격만큼)이다. 2차로·R_in 6,000·W 6,500·간격 300이면 측정선 7,625, 실제 안쪽 차로 중앙 7,925. 측정선 14%일 때 실제 중앙은 약 13.47%, 안쪽 벽 선은 약 17.79%. 즉 **차로 중앙 측정보다 보수적**이지만 안쪽 벽 선보다 엄격하지는 않다. 벽 선 경사는 참고로 기록만 하고 법규 위반으로 만들지 않는다.

**기준 바꾸기(내부 설정, 화면에 노출 안 함)**

| 설정 | 선택지 | 바뀌는 것 |
|---|---|---|
| `radiusReference` | `innerWallFace`(기본) / `innerCurbWallSide` | 후자면 입력 `innerRadiusMm`은 안쪽 연석 벽 쪽 끝 반경. 안쪽 벽 = `innerRadiusMm − 안쪽 벽–연석`. 판정기에는 선택한 선의 반경을 그대로 넘기고 기준을 함께 넘긴다 |
| `widthReference` | `curbWallSides`(기본) / `wallToWall` | 후자면 W = 벽–벽, 연석은 그 안에 놓임 |
| `gradeReference` | `laneCenter`(기본, v0.3) / `conservativeInner` | 후자면 안쪽 벽 + W/4(1차로 W/2). 반경 기준과 무관하게 안쪽 벽에서 잰다 |

## 3. 좌표와 방향

- 진행 방향은 항상 **위층에서 아래층으로 내려가는 방향**이다. 착지점은 아래층 쪽 끝이고 `tangent`는 착지점에서 내려가는 진행 방향(직선 계약과 같은 뜻).
- **내려가며 좌회전이면 안쪽 = 왼쪽, 우회전이면 안쪽 = 오른쪽.** 생성 순서(착지점에서 거꾸로 작도)와 상관없이 이 대응을 유지한다. `section`의 left/right도 이 진행 방향 기준이다.
- **착지점은 법령상 차로 너비 띠의 중앙**(안쪽 연석 벽 쪽 끝 + W/2)에 있다. 아래 직선 길이가 0이면 원호 중심 = 착지점 + (회전 쪽 법선) × `(R_in + 안쪽 벽–연석 + W/2)`. 예: 착지 (0,0), 진행 (1,0), 간격 양쪽 300, W 6,500, R_in 6,000 → 좌회전 중심 (0, 9,550), 우회전 중심 (0, −9,550) (위가 +y).
- 선 구분: 벽 중앙, 차로 띠 중앙(착지점이 놓인 선), 경사 측정선, 바깥 벽은 서로 다른 선이다. 간격이 비대칭이거나 배수 여유가 있으면 벽 중앙 ≠ 차로 띠 중앙.
- **배수 여유 `drainMarginMm`는 바깥 벽만 민다.** 착지점·원호 중심·안쪽 벽·연석·경사 측정선은 움직이지 않는다.

## 4. 입력

```
CurveRampSpec {
  id                               // 필수. 판정기·후보 도형에서 같은 이름으로 쓴다
  systemId                         // 램프 체계(50대 기준은 판정기가 체계 전체 대수로 판단)
  operation?: 'oneWay'|'twoWay', separatedInOut?: boolean   // 판정기로 그대로 전달(없으면 없음 그대로)
  landing:[x,y], tangent:[ux,uy]   // 3장. tangent는 길이 0이 아니면 정규화
  turn: 'left'|'right', turnDeg    // 0 < turnDeg < 360
  innerRadiusMm                    // R_in (2장 radiusReference에 따른 선)
  lanes: 1|2
  legalLaneWidthMm                 // W (2장)
  wallToCurbMm:{inner,outer}       // 기본 300
  curbHeightMm:{inner,outer}       // 기본 150
  curbWidthMm?:{inner,outer}       // 법 규정 없음. 없으면 연석 차로 쪽 선은 미확인
  drainMarginMm?                   // 기본 0
  straightTopMm?, straightBottomMm?  // 위층 쪽·아래층 쪽 직선 길이, 기본 0
  transitions?:{topMm, bottomMm}   // 완화구간 길이(5장 규칙 4)
  levels:                          // 높이 출처(아래 우선순위)
    {connects:{upperLevelMm, lowerLevelMm}} | {floor:{levelMm, heightMm}}
  roadConnection?                  // 상위 계약 1-4 그대로(외곽 밖 지상 접속 구간 선언)
  measurement?                     // 2장 설정. 없으면 기본값
}
```

**높이 출처**: 완전한 connects(두 값 모두 유한한 정수 mm) → 그대로. connects가 아예 없을 때만 `floor.levelMm`(위 끝)과 `floor.heightMm`(아래 끝 = levelMm − heightMm)을 쓰고 결과 `assumptions`에 "층고로 고저차 가정"을 남긴다. connects가 일부만 있으면 층고로 채우지 않고 입력 오류. 위 끝이 아래 끝보다 높아야 한다(음수 고도 자체는 허용).

**입력 오류**(던지지 않고 `violations`에 기록, 몸체는 만들지 않음): id 없음, 유한하지 않은 값, tangent 길이 0, `turnDeg` 범위 밖, R_in·W·간격·직선·완화 길이가 음수이거나 R_in·W가 0 이하, `lanes`가 1·2 아님, connects 부분 입력, 정수가 아닌 고도, 위·아래 높이 역전, 연석 폭 합이 W 이상, 몸체가 스스로 겹침(`SELF_OVERLAP`).

**법정 수치 미달**(반경 5m 미만, W 부족, 경사 초과)은 입력 오류가 아니다. 그대로 만들고 판정기가 실패로 보고한다.

## 5. 생성 규칙

1. 구간은 위→아래 순서로 `[위 완화] → 위 직선 → 원호 → 아래 직선 → [아래 완화]`. 길이 0인 구간은 목록에서 뺀다.
2. **경사용 길이는 실제 길이**: 직선은 그 길이, 원호는 `R_g × θ`(라디안)를 **1mm 아래로 내림한 정수**(내림은 경사를 크게 만드는 쪽이라 보수적). 도면 다각형의 선분 합으로 경사를 재지 않는다.
3. 도면 다각형은 원호를 **처짐(현과 호 사이 최대 거리) 10mm 이하**로 나눈다. 같은 입력이면 같은 꼭짓점.
4. **완화구간**: 입력 길이는 인접 직선 길이 **안에서 떼어 낸다**(더하지 않음). 위 완화는 위 직선의 위 끝, 아래 완화는 아래 직선의 아래 끝. 그 직선이 완화 길이보다 짧으면 완화구간을 만들지 않고 `TRANSITION_NO_ROOM`을 기록한다. 완화구간의 상한은 (완화구간 계약 v0.1 D1) 완화구간이 아닌 구간의 실제 최대 경사의 1/2. `kind:'transition'` 표시는 별표 1 충족을 뜻하지 않으며 R04 확인 불가를 통과로 올리지 않는다.
5. **높이 배분**(모든 고도는 정수 mm, 인접 구간 정확히 연결, 위 끝·아래 끝은 입력과 정확히 같음, 모든 구간이 아래로만 내려감):
   - 구간 용량 `cap_i = floor(상한% × 길이 / 100)`(정수 비교 `h × 100 ≤ 상한 × 길이`를 만족하는 최대 정수).
   - 배분 순서: 원호 → 직선(위·아래는 길이 비례, 내림 후 남는 mm는 위 직선부터 1mm씩) → 완화구간. 각 구간은 용량까지만 받는다.
   - 용량 합이 고저차보다 작으면(길이 부족) 모두 용량까지 채우고 **남은 높이는 원호가 맡는다** → 판정기 R02 실패. 길이를 몰래 늘리지 않는다.
   - 필요한 고저차보다 더 내려갔다가 다시 올라오는 배분(역경사)은 만들지 않는다.
6. 몸체는 기존처럼 실내 면에서 뺀다. 기둥·코어·예약공간과 겹치면 지우지 않고 위반으로 보고한다(79차 원칙).

## 6. 출력

```
CurveRampOut {
  kind:'curve', id,
  body:[[x,y]...],                 // 단일 다각형(360° 미만이라 구멍 없음). 바깥 벽–안쪽 벽, 직선 포함
  innerWall, outerWall:[[x,y]...],
  curbs:{inner:{wallSide, trafficSide|null}, outer:{...}},   // 폭이 없으면 trafficSide null(미확인)
  gradeLine, laneBandCenter:[[x,y]...],
  landing, tangent, start,         // start = 위 끝(차로 띠 중앙)
  widthMm:W, wallToWallMm, lanes, turn, turnDeg, innerRadiusMm,
  segments:[{id, kind, lengthMm, startLevelMm, endLevelMm}],   // 5장
  referenceSlopes:{innerWallPct, gradeLinePct, laneCenterPct, outerWallPct},  // 원호만, 참고값
  measurement:{radiusReference, widthReference, gradeReference, basis:'관행·보수적 선택', decided:'사용자 2026-10-26'},
  assumptions:[...],               // 예: 층고로 고저차 가정
  evaluatorRamp:{                  // 판정기 PlanningInput.ramps[] 한 개
    id, systemId, operation?, separatedInOut?, lanes,
    shape:{type:'curve', innerRadiusMm, lengthMm},   // lengthMm = segments 길이 합(정확히 같음)
    section:{legalLaneWidthMm:W, wallToWallMm,       // 실제 벽 간격(배수 여유 포함)
             wallToCurbMm:{left,right},              // 실제 거리. 바깥 쪽은 간격 + 배수 여유
             curb:{left:{heightMm, widthMm?}, right:{heightMm, widthMm?}}},
    segments, connects:{upperLevelMm, lowerLevelMm}, roadConnection?, measurement, assumptions
  },
  candidateRamp:{id, bodyPolygon:body, segments},    // 후보 도형 geometry.ramps[] 한 개(상위 계약 3장)
  violations:[...]                 // 입력 오류·몸체 충돌·TRANSITION_NO_ROOM. 법규 판정은 넣지 않음
}
```

- 법규 자료(`evaluatorRamp`)와 몸체(`candidateRamp`)는 **둘 다** 판정기로 간다. 법규 자료만 넘기면 겹침·외곽·착지 접속은 확인되지 않는다.
- left/right는 3장 대응(좌회전이면 inner=left)으로 채운다.
- `measurement`·`assumptions`는 판정기 결과의 근거(evidence)에 옮겨 적혀야 한다. 지금 판정기는 이를 읽지 않으므로 구현 단위에서 옮겨 적기만 추가한다(7장). 숫자 판정은 바꾸지 않는다.

## 7. 상위 계약 보완안 (CONTRACT.md, 반영은 구현 단위에서)

1. 1-4 표에 선택 필드 `ramp.measurement`, `ramp.assumptions` 추가. 판정기는 숫자 판정에 쓰지 않고 해당 램프 항목의 evidence에 그대로 옮긴다. 없으면 아무 것도 하지 않는다(기존 결과 불변).
2. 5-5 R02 첫 줄 뒤: "곡선 생성기가 낸 구간의 lengthMm는 그 생성기가 선언한 경사 측정선 위 실제 길이다. 판정기는 길이를 다시 재지 않으며 선언을 evidence에 옮긴다. 선언이 없는 기존 자료는 지금과 똑같이 판정한다."
3. R03: "내변반경 입력이 어느 선의 반경인지는 measurement.radiusReference로 선언한다. 없으면 기존과 같이 입력값을 그대로 쓴다."
4. 하지 않는 것: 선언 없는 자료 거부, 구간 kind 누락을 shape.type으로 채우기, 기존 길이·반경을 새 측정선으로 다시 계산하기, 50대 이하 5m 분기 변경.

## 8. 통과 조건

### 8-1. 법규(판정기가 낸다)

| 항목 | 판정기 ID | 조건 |
|---|---|---|
| 차로 너비 | R01 | 곡선 1차로 W ≥ 3,600, 2차로 W ≥ 6,500. 50대 이상은 6m 이상 2차로 또는 진입·진출 분리(분리 여부 미상이면 확인 불가) |
| 경사 | R02 | 원호 ≤ 14%, 직선 ≤ 17%, 정수 비교 |
| 내변반경 | R03 | R_in ≥ 6,000, 체계 전체 50대 이하면 5,000 |
| 완화구간 | R04 | 50대 이상이면 별표 1(50–99대 볼록 1.7m, 100대 이상 볼록 1.7m·오목 2m). 구간 계산 미구현이면 확인 불가 |
| 연석 | R09 | 벽–연석 ≥ 300, 높이 100–150 |

- 곡선 램프는 판정기 결과 없이 성립(FEASIBLE)으로 표시하지 않는다. 계획 엔진의 직선 17% 검사(`RAMP_SLOPE`)를 곡선에 쓰지 않는다.
- 관행 기준의 PASS는 PASS로 두고 결과 옆에 측정 기준을 표시한다(사용자 위임, Claude 결정 2026-10-26).

### 8-2. 도형·동선(판정기 G·R08, 계획 엔진)

1. 몸체가 매스 안. 외곽 밖 지상 접속은 `roadConnection.outsidePolygon`으로만 허용.
2. 기둥·코어·예약공간·주차칸과 겹치지 않음. 기둥은 이름·위치·도형 전부 보존.
3. 착지점에서 폭 있는 진입로가 순환 차로에 닿음(R08, 현행 접속 재사용).
4. 같은 입력이면 같은 결과. 이동·회전·좌우 대칭에도 같은 대수·판정.
